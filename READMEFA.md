# کوییز کلاب

[English](README.md)

یک مسابقهٔ دو نفره که روی سیستم خودت اجرا می‌شه. یک نفر اتاق می‌سازد، لینک دعوت را می‌فرستد، و هر دو نفر به نوبت به سؤال‌های یکسان جواب می‌دهند. جواب درست ۱۰ امتیاز دارد و اگر در نیمهٔ اول زمان ۳۰ ثانیه‌ای ثبت شود، ۳ امتیاز اضافه هم می‌گیرد.

## پیش‌نیاز

- پایتون ۳.۱۰ یا جدیدتر

## اجرا

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export GEMINI_API_KEY="your Google AI Studio API key"
python app.py
```

بعد[http://127.0.0.1:5000](http://127.0.0.1:5000) را باز کنید.
می‌توانید کلید را به‌صورت `GEMINI_API_KEY=your-key` در فایل `.env` در پوشهٔ پروژه قرار دهید؛ برنامه هنگام اجرا آن را می‌خواند. پس از ویرایش `.env` برنامه را دوباره اجرا کنید. کوییز کلاب برای ساخت پنج سؤال تازه در هر مسابقه به `GEMINI_API_KEY` نیاز دارد و سؤال‌ها را با Gemini می‌سازد. برنامه سؤال‌ها را از `questions.json` نمی‌خواند. کلید را محرمانه نگه دارید و در مخزن قرار ندهید. اگر کلید تنظیم نشده باشد یا ساخت سؤال شکست بخورد، خطا نمایش داده می‌شود و مسابقه با سؤال محلی شروع نمی‌شود.
مدل پیش‌فرض `gemini-3.5-flash-lite` است. در صورت نیاز می‌توانید با `GEMINI_MODEL` در فایل `.env` مدل دیگری تنظیم کنید.
خطاهای API در فایل `quiz_game.log` در پوشهٔ پروژه ثبت می‌شوند. جزئیات خطا نوشته می‌شود، اما خود کلید API در گزارش ذخیره نمی‌شود. این فایل در Git نادیده گرفته شده است.

| متغیر | پیش‌فرض | کاربرد |
|---|---|---|
| `HOST` | `127.0.0.1` | آدرسی که سرور روی آن گوش می‌دهد |
| `PORT` | `5000` | درگاه سرور |
| `SECRET_KEY` | یک مقدار مخصوص توسعهٔ محلی | کوکی نشست را امضا می‌کند. پیش از اینکه سرور را با دیگران به اشتراک بگذارید این مقدار را عوض کنید. |
| `GEMINI_API_KEY` | ضروری | کلید Google AI Studio برای ساخت سؤال‌های تازه در هر مسابقه. |
| `APP_DEBUG` | تنظیم نشده | اگر `1` باشد، با تغییر کد سرور دوباره بارگذاری می‌شود. |

## بازی

1. دسته‌بندی سؤال را انتخاب کنید، اسمتان را وارد کنید و یک اتاق بسازید.
2. لینک اینوایت را برای بازیکن دیگر بفرستید. اسم او باید با اسم شما فرق داشته باشد.
3. هر دو نفر آماده را بزنند. مسابقه با نوبت میزبان شروع می‌شود.
4. پیش از تمام شدن زمان، یکی از گزینه‌های A تا D را انتخاب کنید. بعد نوبت به بازیکن دیگر می‌رسد.
5. وقتی هر دو جواب دادند، نتیجهٔ دور را ببینید و با هم ادامه دهید.
6. با تمام شدن سؤال‌ها، صفحهٔ نتایج برنده را نشان می‌دهد. در تساوی برنده‌ای اعلام نمی‌شود.

بردها و مجموع امتیازها در تالار مشاهیر صفحهٔ اصلی نگه داشته می‌شوند. اول تعداد برد ملاک است، بعد امتیاز.

Gemini برای هر مسابقهٔ جدید پنج سؤال می‌سازد؛ از سؤال‌های محلی استفاده نمی‌شود.

## ساختار

| مسیر | نقش |
|---|---|
| `app.py` | مسیرهای FastAPI: اتاق، نوبت، گفتگو، نتایج |
| `engine.py` | قانون امتیاز (`Question`، `Match`، `Chat`) |
| `storage.py` | جدول امتیاز JSON، ثبت جواب‌ها در SQLite |
| `templates/` | صفحه‌های خانه، پیوستن، بازی و نتایج |
| `tests/` | تست موتور، ذخیره‌سازی و جریان وب |

اتاق‌های فعال فقط در حافظه هستند و با توقف برنامه از بین می‌روند. مسابقه‌های تمام‌شده همچنان `leaderboard.json` را به‌روز می‌کنند و هر جواب در `quiz.db` نوشته می‌شود. هر دو فایل در اولین استفاده ساخته می‌شوند و در گیت نادیده گرفته شده‌اند.
